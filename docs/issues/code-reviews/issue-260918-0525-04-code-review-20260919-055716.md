### M1. The fixture key oracle is read before delivery is known to be complete (FIXED)
> **Fix:** `send_sentinel_and_wait` records the sentinel count before sending and waits for it to increase, so each barrier (including the post-JSON one) waits for its own new sentinel. Red/green: sending the key in the JSON refusal path failed all five refusal tests; restoring the guard passed them.

**Source:** CLAUDE-1, CODEX-4 (both reviewers agree; merged)
**Files:** `tests/integration.rs:1216`, `tests/integration.rs:3731-3732`, `tests/integration.rs:3772-3773`, `tests/integration.rs:3782-3785`, `tests/integration.rs:3876-3877`

Each refusal test reads the fixture's `--report` once, right after the CLI exits, and asserts that no key event is present. `read_report` treats a missing or unreadable file as empty (`unwrap_or_default`), and fixture report writes are asynchronous. So a wrong report path, or a key that tmux has not yet delivered, passes the "no key reaches the fixture" check. The send tests stop at the first observed key event (`wait_for_key_count` returns at count == 1), so a forbidden second key sent after the declared key (e.g. `C-c` after `C-u`) goes unobserved. The acceptance criteria "no key reaches the fixture" and "the fixture receives the declared key, not `C-c`" are only apparently verified.

**Recheck (both reviewers: STILL_BROKEN):** the correction added a `C-g` sentinel barrier (`send_sentinel_and_wait`, `keys_before_last_sentinel`). It works for the send tests and the concise half of each refusal test. `assert_interrupt_refused` calls the barrier a second time after the JSON run, but `send_sentinel_and_wait` (`tests/integration.rs:3711-3720`) waits only until *any* sentinel exists. So that second wait returns on its first poll, and a key delivered by the JSON-format interrupt can go unobserved in all five refusal tests. The barrier must wait for a *new* sentinel, for example by recording the sentinel count before sending and waiting for it to increase, or by clearing or rotating the report between runs.

**Required outcome:** after every `interrupt` in these tests, send a known sentinel through the same pane input path and wait for it to appear in the fixture report. Then assert the exact key-event sequence before the sentinel: empty for refusals, exactly the declared key for sends (e.g. `[0x15]` for `C-u`, `[0x03]` for `C-c`). A missing report must fail the test, not read as empty.

### M2. `interrupt` now fails on a malformed surface pattern instead of sending on a no-hazard surface (FIXED)
> **Fix:** `interrupt_surface_for` resolves key/hazard without compiling patterns; no-hazard sends, hazardous-unvalidated refuses before compile, validated-hazardous compile failure refuses with no key; three CLI tests.

**Source:** CODEX-2 (Claude agrees: a regression)
**Files:** `src/cmd/interrupt.rs:44`, `src/cmd/wait_idle.rs:136-141`

`interrupt` calls `surface_info_for`, which compiles the surface's `ready_regex`/`busy_regex` with `?` before `interrupt` checks `quit_when_idle`. Registry load does not validate those regexes. So a surface declaring no quit hazard, with a malformed pattern, makes `interrupt` exit with a regex error and send nothing. That breaks "a surface declaring no quit hazard sends its declared key on every state result". Before this diff, `interrupt` never read the registry. For a hazardous surface-unvalidated pane, the same ordering replaces the required refusal and its guidance with a regex error. That still fails safe, because no key is sent.

**Required outcome:** resolve the surface's key and hazard without compiling patterns. Send immediately on a no-hazard surface. Refuse a hazardous surface-unvalidated pane with its guidance. Compile and classify only for a validated hazardous pane. There, a pattern-compile failure must still refuse, sending no key. Add CLI-seam tests for (a) a no-hazard surface with a malformed regex: the key is sent; (b) a hazardous surface-unvalidated pane with a malformed regex: the surface-unvalidated refusal is issued and no key is sent.

### M3. The unknown-state refusal gives guidance that cannot succeed when the surface has no patterns (FIXED)
