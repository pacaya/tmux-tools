# Code review — ISSUE-261107-0921-03 (Orca backend)

Base: `0f8c0b41c93aa5255e5075a846ff993f9617299e` · Reviewers: Claude, Codex · Bundle: `.planning-contracts/bundles/ISSUE-261107-0921-03` (canonical)

### H1. Reconciliation deletes the record of a concurrently spawned live pane (FIXED)
> **Fix:** records are loaded before `terminal list`; a changed record is re-read and kept before any delete; concurrent-spawn regression.
Sources: CLAUDE-1, CODEX-1. `core/src/host/orca.rs:297-307` (callers `find_registered` ~900, `list_panes` ~624, `pane_names` ~836). `terminal list` is taken before `checked_records` loads the registry (after an `orca status` call). A spawn that creates its pane and writes its handle (orca.rs ~1034) between the two is judged `dead` against the stale complete list, and its record is deleted; the pane stays open unregistered. Violates PRD-261107-0825-01 P4.4–P4.5 (brief: "Implement … P4 … as written").
BLOCKER. Required outcome: a record whose handle was written after the pane-list snapshot is never classified `dead` (load records before the list, or revalidate an apparently-dead handle against a fresh list before deleting). Deterministic regression for the interleaving.

### H2. Valid leading-dot names are invisible in the registry (FIXED)
> **Fix:** `load_all` loads every `*.json` incl. leading dot; `.tmp` temp files skipped; `.hidden` CLI regression.
Source: CODEX-2. `core/src/registry.rs:212-215`. `.hidden` satisfies P4.1, but `load_all` skips every file whose name starts with `.`, so `list`, name targets, `self` and `kill` ownership ignore its record. Violates P4.1 and P9.12.
BLOCKER. Required outcome: load every valid record file regardless of its first character; exclude temp files by their temp-file form. CLI regression for `--name .hidden` through spawn/list/target/kill.

### M1. An installed Orca CLI with an unreachable runtime does not name the selection source (FIXED)
> **Fix:** reachability error codes carry the selection source on every orca call; 8-verb runtime-unavailable regression.
Sources: CLAUDE-2, CODEX-7. `core/src/host/orca.rs:186-210, 253, 624`. Only `status()` maps an `ok:false` answer to the source-aware unreachable error; `terminal list` and other first calls surface a raw `OrcaError` (`runtime_unavailable`, …) without `ORCA_TERMINAL_HANDLE`. Violates the acceptance item "Given only `ORCA_TERMINAL_HANDLE` set and no reachable Orca runtime, `list` exits 1, stderr names `orca` and `ORCA_TERMINAL_HANDLE`" and P3.4.
BLOCKER. Required outcome: every runtime-reachability error from any orca call names host and selection source. Test with a shim `orca` that answers a runtime-unavailable error for every command.

### M2. An empty `TMUX_TOOLS_HOST` silently selects a host (FIXED)
> **Fix:** a present empty override goes through validation and fails naming tmux and orca; CLI regression.
Source: CODEX-3. `core/src/host/mod.rs:91`. `filter(|v| !v.is_empty())` treats `TMUX_TOOLS_HOST=""` as unset. The approved contract says values `tmux` | `orca`; "any other value is an error (P3.1)".
BLOCKER. Required outcome: a present but empty `TMUX_TOOLS_HOST` exits 1 naming `tmux` and `orca`, like any other invalid value. CLI regression.

### M3. Failed spawn cleanup releases the reservation while the pane stays open (FIXED)
> **Fix:** reservation released only after a successful close; failed close keeps it and reports both failures; regression.
Source: CODEX-4. `core/src/host/orca.rs:~1036`. When the handle write fails, the `terminal close` result is ignored and the reservation is deleted unconditionally (also after `--retry-split` recovery). Violates P4.4 (write the recovered handle or close that pane before releasing its reservation).
BLOCKER. Required outcome: release the reservation only after a successful close; on close failure keep the reservation and report the unresolved pane and the failure. Cover with a shimmed failure path.

### M4. The live suite cannot close panes from a failed spawn call (FIXED)
> **Fix:** run-owned pane tracking before the outcome check, bounded final re-scan for late arrivals; late splits owned through the recorded tab of a run-owned split target (`anchor_split`); live P10.3 split targets a run-owned anchor; fake-CLI late-tab and late-split regressions.
> **Recheck 2:** STILL_BROKEN (Codex) — a late split from a timed-out call has no record, no shim receipt and no title (`terminal split` gets no name), so it is never tracked; reproduced with `launch --split h` on the fake CLI. Required: run-specific split identity (e.g. a late pane that appears in the tab of a run-owned split target after the run's split call is owned) and a regression for that path.
> **Recheck 1:** STILL_BROKEN (Codex) — discovery ends at the post-call snapshot, so a pane that opens late after an ambiguous timeout (P9.2) is never tracked or closed; reproduced with a fake CLI. Required: also track run-owned late arrivals through final reconciliation before the run ends.
Source: CODEX-5. `tests/contract/orca.rs:~250`. `Run::spawn` asserts success and parses stdout before tracking the handle, so a pane created by a failing/timing-out call is never closed by final cleanup or `Drop`. Violates P10.4 ("Every pane a contract run creates is closed by that run, also on failure").
BLOCKER. Required outcome: track created panes independently of CLI success (e.g. diff `orca terminal list` around each spawn) and close them on every failure path.

### M5. Child-process environment isolation does not cover the whole default suite (FIXED)
> **Fix:** load-time `core/src/test_child_env.rs` initializer sanitizes env and PATH in core unit, bin unit and integration executables.

Violates the default-run acceptance item "Every child process of the default suite runs without `TMUX_TOOLS_HOST`, `ORCA_TERMINAL_HANDLE` and `ORCA_WORKTREE_ID`, and with no real `orca` on its `PATH`, unless the test sets them."

### L1. `list --format json` on Orca runs two extra orca calls per row (FIXED)
> **Fix:** batch `host_states`; `list --format json` runs one `worktree ps` and no `terminal show` for listed panes.
Source: CLAUDE-3. `src/cmd/list.rs:185`, `core/src/host/orca.rs:409-421`. `host_state` per row runs `terminal show` plus a full `worktree ps`, re-fetching the same answer N times. No acceptance item covers it; performance defect.
Required outcome: fetch `worktree ps` (and the shown terminal data) once per invocation for `list`.

### H3. Live-suite cleanup can close panes the run did not create (FIXED)
> **Fix:** cleanup closes only panes with run-specific evidence (private-registry record, shim create/split receipt, or run-tagged `paneTitle`); unrelated-pane fake-CLI regression.
> **Routing:** RETAINED_REGRESSION: H3, M4 — batch 2 on route claude (regression, tests only, effort medium).
Sources: CLAUDE NEW-1, CODEX NEW-1 (introduced by the M4 fix). `tests/contract/orca.rs:249-270, 336-351`. `cli_creating` treats every handle that appears in the run's `ORCA_WORKTREE_ID` during a creating call as run-created; `close_created` then runs `kill --any --force` and real `orca terminal close` on it. A pane that the user, another session or a parallel teammate opens in that worktree during the call is closed (Codex reproduced it with the actual `Run` methods and a fake CLI). P10.4 requires closing the panes the run created, not other panes; destructive.
BLOCKER. Required outcome: close only panes with run-specific ownership evidence (e.g. a Pane record under the run's own `XDG_STATE_HOME`, or a run-unique marker in the pane's name/title/command). Fake-CLI regression: an unrelated pane opened between snapshots survives cleanup.

### M6. Concurrent `Run`s can share one private registry directory (FIXED)
> **Fix:** `unique_dir` (pid-ms-atomic seq, exclusive create) for Run and FakeCli, tag includes seq; concurrent-runs regression.
Source: CODEX recheck-2 NEW-1 (introduced by batch 2). `tests/contract/orca.rs:~107`. `Run::with_orca` names its directory and ownership tag from process id + millisecond time only; the two new default tests run concurrently and chose the same directory in a targeted run, and a probe showed one Run's `Drop` (~:485) removing the other's registry, so its pane stayed open and name capture failed. Breaks the run-specific evidence P10.4 cleanup depends on.
BLOCKER. Required outcome: each Run gets an atomically unique directory (e.g. `tempfile`/`mkdtemp`-style or a process-wide atomic counter) and a tag derived from that unique identity; a regression that two concurrently created Runs never share a directory and one Run's teardown leaves the other's records and receipts intact.
