### M1. Empty prompt fails in paste-buffer and never sends Enter (FIXED)
> **Fix:** empty text skips load/paste, reads the live flag for the outcome, and still sends Enter; CLI test `prompt_empty_text_still_submits_with_enter_and_leaves_no_buffer`.

**Source:** CLAUDE-1, CODEX-4 (both reviewers agree)
**Files:** `src/cmd/prompt.rs:239-252`

`prompt` still accepts `""` as TEXT. Before this change, empty text sent no chunks and then one Enter. Now `load-buffer -b <name> -` on empty stdin exits 0 but creates no buffer, so `paste-buffer -p -d -b <name>` fails with "no buffer". `prompt` then exits non-zero with a misleading transport error and never sends Enter. P1 changes the transport; it does not remove the empty-prompt case.

**Required outcome:** for empty text, skip `load-buffer` and `paste-buffer`, still send Enter as before, report the live delivery outcome, and leave no prompt buffer. Add a CLI-seam test with `tt-fake-tui` that checks exit 0, the reported outcome, and an empty `tmux list-buffers` for prompt buffers.

### M2. The live flag is read before load-buffer, not immediately before paste (FIXED)
> **Fix:** pre-load refusal kept; a second `bracket_paste_flag` read after load decides and reports the outcome, and a refusal there deletes the buffer and exits non-zero; wrapper-driven CLI test `prompt_refuses_when_flag_clears_between_load_and_paste`.

**Source:** CODEX-1 (Claude: PARTIAL, a second read before paste is warranted; severity lowered from HIGH)
**Files:** `src/cmd/prompt.rs:104-117`, `src/cmd/prompt.rs:239-252`

P1 keys the guarantee to "`bracket_paste_flag`, read immediately before pasting", and the Agent Brief says "read right before pasting". The code reads the flag once, before `load-buffer`, and reports that outcome. Pasting is a separate, later tmux command. If the target turns bracketed paste off in that gap (the agent exits to its keep-alive shell), `prompt` reports `guaranteed` for a paste tmux did not bracket.

**Required outcome:** keep the existing pre-load read that refuses multi-line text before `load-buffer` (P1's refusal clause). After a successful load, read `bracket_paste_flag` again immediately before `paste-buffer`, and use that read to decide and report the outcome. If the second read now calls for refusal (flag clear, surface declares the capability, text is multi-line), delete the loaded buffer, report the refusal on stderr (raw and concise) and in the JSON field, and exit non-zero without pasting. Emit the delivery notice from the final read. Atomicity with paste in a single tmux command is not required. Add a deterministic CLI-seam test that flips the pane's flag between load and paste, for example with the existing tmux-wrapper interposition used by the paste-failure test, and asserts the refusal, that nothing reached the fixture, and that no prompt buffer remains.

### M3. The fixture counts pastes, not submissions, so "exactly one submission" is not observed (FIXED)
> **Fix:** `tt-fake-tui` keeps a composer and records `submission` only on Enter; acceptance tests assert exactly one submission equal to the payload; `prompt`'s Enter dispatch unchanged.

**Source:** CODEX-2, narrowed (Claude agrees on the oracle half). The repeat-Enter half is out of scope: `dispatch_enter(true, true, …)` is unchanged from base `4d1635f:src/cmd/prompt.rs:138`.
**Files:** `src/bin/tt-fake-tui.rs:134-144`, `tests/integration.rs:2940-2962`, `tests/integration.rs:3014-3017`

The acceptance criterion requires "the fixture reports exactly one submission whose text matches what was sent". `tt-fake-tui` writes a `paste` record when the closing bracket arrives, before any Enter, and the tests count `paste` records. The test would still pass if `prompt` never sent Enter, so submission is not observed at the seam.

**Required outcome:** `tt-fake-tui` holds pasted text as composer state and writes a `submission` record carrying the composed text only when Enter (CR) arrives. The acceptance tests assert exactly one `submission` whose text equals what was sent (as the fixture reports it). Keep the no-bracketed-paste path's reporting consistent with this model. Do not change `prompt`'s Enter dispatch.

### M4. A failed second flag read leaks the loaded prompt buffer (FIXED)
> **Fix:** the post-load flag-read error arm deletes the buffer and returns the original error; wrapper-driven CLI test `prompt_post_load_flag_read_failure_leaves_no_prompt_buffer`.

**Source:** CLAUDE-2, CODEX-RECHECK-1 (both reviewers; introduced by the M2 repair; verified directly)
**Files:** `src/cmd/prompt.rs:268-289`

In `deliver_prompt`, `determine_delivery(...)?` runs after a successful `load-buffer`. If the second `bracket_paste_flag` read fails (for example the pane dies or the target becomes invalid between load and read), `?` returns before either `delete-buffer` branch, so the prompt text stays in tmux's paste buffers. This violates P1: "The buffer is deleted on every path after a successful `load-buffer`".

**Required outcome:** when the post-load flag read fails, delete the named buffer before returning, and return the original read error unchanged (cleanup does not replace it). Add a CLI-seam failure-injection test, using the existing tmux-wrapper interposition, that makes the post-load flag read fail and asserts a non-zero exit, the original error on stderr, and no prompt buffer in `tmux list-buffers`.
