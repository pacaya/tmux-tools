### M1. Live-run teardown skips the recorded block ids when the block listing fails (FIXED)

> **Fix:** `LiveRun` teardown closes every recorded block id directly, each close caught on its own, before the label listing, which is now only an extra pass.

`tests/contract/rex.rs:2660-2683` (`impl Drop for LiveRun`), `:2564-2578` (`own_blocks`) (source: CODEX-1). Brief Required change, first bullet (P8.6 teardown); PRD-261112-2108-01 P8.6: every block a run creates is closed by that run, also on failure. `Drop` kills by pane name, then closes only the blocks that `own_blocks()` finds through `all_blocks()`. When that listing panics (for example `rex ls --json` fails), `catch_unwind(...).unwrap_or_default()` gives an empty list, so the block ids already stored in `created` are never closed, even when `rex block close <id>` still works. A failed live run can leave its Claude and `--split v` blocks open on the default server.
CHANGE: in teardown, run `rex block close <id>` for every id in `created` (never the caller's block) independently of any listing result; use the label listing only as an extra pass for creates whose id is unknown.
