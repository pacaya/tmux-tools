### M1. A successful fast respawn returns a refusal (FIXED)
> **Fix:** on Herdr, a failed name write after create+close completes the respawn when `pane_exists(new)` is `Ok(false)`; fake hc `FAKE_HC_EXEC=wait`; regression `on_herdr_a_respawn_whose_command_exits_0_at_once_succeeds`.

- File: `src/shim.rs:877-881`
- Source: codex CODEX-1; claude AGREE
- Description: `respawn-pane -k` on Herdr creates the replacement with `--rm` (PRD-261115-0921-01 P6.1), closes the old terminal, then writes the name (P5.1). When the replacement command exits 0 before that label write, Herdr has removed it, `hc label` fails `not_found`, and the Shim exits 1 (`tmux: hc label: not_found: no terminal "t3"`) although the create succeeded and the old terminal is closed. PRD-261108-0447-01 P6.2 allows exit 1 only when the create fails. Reproducible with `FAKE_HC_EXEC=1` and `respawn-pane -k -t %2 -- true`.
- Recommended fix: treat a replacement already removed after a successful create as a completed respawn (exit 0); keep the error when the label write fails on a terminal that still exists. Add a fake-hc regression for an immediately successful respawn command.

### M3. Closing a `--rm` Teammate terminal fails on real Herdr (FIXED)
> **Fix:** Herdr `close_pane` treats `not_found` from `hc kill` as already gone, then removes as before; fake hc `kill` of a `--rm` terminal removes it and answers `not_found` exit 3; regressions for Shim respawn/kill-pane and `kill --target`.

- File: `core/src/host/herdr.rs:916-919`
- Source: P8 live run (orchestrator, direct verification against the real `hc`)
- Description: real `hc kill` on a terminal started with `--rm` ends the program, Herdr removes the terminal at once, and `hc kill` itself exits 3 with `{"error":{"kind":"not_found","message":"t1t was removed"}}` (probe: `hc run --bg --rm … -- sleep 600; hc kill <t>`). Herdr `close_pane` runs `hc kill` with `?` and treats "already removed" as success only for `hc rm` (P7.4), so every close of a Teammate terminal (PRD-261115-0921-01 P6.1 `--rm`) fails. Live effect with Claude 2.1.325: `split-window` (no command) then `respawn-pane -k` → `tmux: hc kill: not_found: t1p was removed`, the new terminal is also lost, and Claude's teammate start fails; the same path breaks `kill-pane`, the Leader-exit close (P8.4), and `kill --target` (P8.5). The fake `hc` does not model this, so the suite passed.
- Recommended fix: in Herdr `close_pane`, treat a `not_found` answer from `hc kill` as the terminal already gone (success), then keep the removal step's existing "already removed is success" rule. Make the fake `hc` model real behavior: `kill` of a `--rm` terminal removes it and answers `not_found` "`<t>` was removed" with exit 3. Add regressions through the Shim (`respawn-pane -k` and `kill-pane` on a Herdr teammate) and through `tmux-tools kill --target` on a `--rm` teammate.
