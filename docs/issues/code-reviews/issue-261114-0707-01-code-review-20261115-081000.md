### M1. Prompt settle can end on a Host state published before the transmission (FIXED)

> **Fix:** Rex records the send boundary immediately before the paste; `prompt` gates the settle on `HostPort::send_boundary_ms`; CLI regression added.

`src/cmd/prompt.rs:292`, `core/src/host/rex.rs:1527-1540` (source: CODEX-1). PRD-261112-2108-01 P6.8: a Host state may end the settle only when its record is newer than the send. `prompt.rs` takes `submitted_ms` before `host.submit_prompt`; `RexHost::submit_prompt` then reads `program_status` and lists sessions/blocks before the paste and before it sets `Pending.sent_ms`. A terminal record published in that window counts as "after the send" (`core/src/idle.rs:280`) and ends the settle early.
CHANGE: on Rex, settle eligibility uses the backend's actual send boundary (the same instant as `Pending.sent_ms`, taken immediately before transmission). Add a deterministic fake-rex CLI test that publishes a terminal `program_status` during the pre-send listing and shows it cannot end the settle.

### M2. A timed-out or unparseable listing call ends the verb instead of making the listing incomplete (FIXED)

> **Fix:** Timeout, unparseable, or array-less listing answers become `NoAnswer` and make the listing incomplete; CLI cases for `rex ls` and `block ls`.

`core/src/host/rex.rs:310`, `:316-322`, `:371-396`, `:973` (sources: CODEX-3, CLAUDE-2). PRD-261112-2108-01 P4.3 adopting PRD-261107-0825-01 P4.5: a listing is complete only when every call succeeds; an incomplete listing keeps records, shows unlisted rows as `unknown`, prints `list incomplete: rex`, and fails only unlisted names with `pane list incomplete: <name>`. Only `RexError` (non-zero exit) marks it incomplete; a timeout (plain error) or exit-0 non-JSON output propagates and exits 1 — for both `rex ls --json` and `rex block ls -s <session> --json`.
CHANGE: treat a timed-out or unusable `rex ls` / `rex block ls` response as an unsuccessful listing call (incomplete), keeping successfully listed sessions and records. Cover the timeout and invalid-JSON paths at the CLI seam.

### M3. Private-server teardown can panic before it stops the server and deletes its directory (FIXED)

> **Fix:** `PrivateServer::stop` is best effort and non-panicking; it always kills and reaps the child and deletes the directory.

`tests/contract/rex.rs:1792-1813` (source: CODEX-4). PRD-261112-2108-01 P8.3/P8.6 and the last acceptance item: the run stops the private server and deletes its directory at the end, also on failure. `stop()` takes the child, then calls `self.blocks()` → `rex_json`, which panics on a crashed/unreachable server or non-JSON output; kill, wait and `remove_dir_all` are skipped, and a second panic during unwinding (from `Drop`) aborts the process.
CHANGE: make teardown best effort and non-panicking — tolerate listing/close failures, always kill and reap the child, and always delete the private directory.

### L1. Millisecond truncation can select an older Host state record (FIXED)

> **Fix:** Newest-record selection uses nanosecond `updated_at`; sub-millisecond CLI regression added.

`core/src/host/rex.rs:486-491`, `:876` (source: CODEX-2). PRD-261112-2108-01 P6.2: the Host state comes from the record with the newest `updated_at`. `rfc3339_ms` drops sub-millisecond digits and `max_by_key` returns the last of equal maxima, so `working @ .570900Z` listed before `idle @ .570100Z` selects `idle`.
CHANGE: compare full timestamp precision when selecting the newest record; add a CLI regression with two records less than 1 ms apart in the order that currently fails.
