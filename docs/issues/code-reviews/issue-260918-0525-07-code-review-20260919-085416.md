### H1. claude's flat surface was made the default on patterns that come from an optional user status line (FIXED)
> **Fix:** claude default back to `rich`; built-in claude flat carries no readiness patterns; status-line patterns moved to the opt-in `examples/claude-statusline/agents.toml`; README/CONTEXT/smoke note updated.

**Source:** CLAUDE-1 + CODEX-1 (both reviewers)
**Files:** `core/src/agents/builtin.rs:141-162`, `README.md` (claude surface section), `CONTEXT.md`, `examples/claude-statusline/agents.toml`, `tests/integration.rs`

The built-in claude `flat` surface ships `ready_regex` `(✓ done|⏸ waiting) \| 🤖` and `busy_regex` `⚡ working \| 🤖`, stamped `claude 2.1.278`, and is `default_surface`. Those strings appear only in the output of the optional `examples/claude-statusline` status line, which the user installs through `~/.claude/settings.json`. Plain `claude --ax-screen-reader` has no native idle or busy chrome, so on a default install every pane classifies as Unknown and `wait-idle` completes by idle fallback. P2 allows promotion only once the flat rendering ships a pair "measured against the live binary", and says idle-only completion is not an acceptable basis. The smoke's claude.flat PASS validated the maintainer's augmented setup, not the binary.

**Required outcome:** with no surface named, built-in claude resolves to and records its pre-surface rendering (`rich`). The built-in claude flat surface does not carry stamped patterns that depend on the optional status line. Those patterns may live in the opt-in `examples/claude-statusline/agents.toml` as a user declaration. The smoke and README record that claude's flat rendering has no native ready/busy chrome, and claude therefore keeps its former default. codex and the README-documented dsh declarations are unaffected. Update tests, README and CONTEXT to match.

### H2. Large-paste check passes input that was dropped or split (FIXED)
> **Fix:** 101-line (~5 KB) payload; markers searched only in the composer region; exactly one full-size placeholder (or the inline sentinel for dsh flat) required via `composer_paste_evidence`; any busy frame, history growth, unsettled pane or non-Idle classification fails; unit-tested plus a live no-bracketed-paste negative control.

**Source:** CODEX-5 (Claude agrees)
**Files:** `src/bin/tt-vendor-smoke.rs:476-525`

`check_large_paste` sleeps 2s, takes one capture and passes on any state other than Busy, including Unknown; on a surface with no patterns it passes on `idle_evidence` alone. The `END-MARKER-9Z` sentinel written into the payload is never looked for in the capture. A paste that was dropped entirely passes. So does a fragmented one whose turn start is not classified Busy within 2s. P8 requires "a large paste still arriving as one submission".

**Required outcome:** the check passes only when the whole payload, including its end sentinel, is visible in the composer, and no turn started (no Busy frame, or other positive turn evidence) across a sampled stability window. A missing sentinel, an observed turn, or an unclassifiable state is a surface failure.

### M1. Quit-when-idle is measured without first confirming the pane is idle (FIXED)
> **Fix:** quit key sent only after `wait_for_stable_idle` (native boot chrome + byte-stable window); timeout/capture error is a surface failure.

**Source:** CODEX-4 (Claude agrees)
**Files:** `src/bin/tt-vendor-smoke.rs:288-296`, `src/bin/tt-vendor-smoke.rs:457-467`

`check_busy` discards the result of its post-turn idle wait (`let _ = wait_for(... Idle ...)`), and the quit check then sends `interrupt_key` unconditionally. If the generating turn outlasts the 45s wait, the key interrupts generation instead of testing quit-at-idle. A surface wrongly declared `quit_when_idle = false` therefore passes.

**Required outcome:** the quit check sends the interrupt key only after positive, independently established idle evidence (see M3). A timeout or capture failure before that point is a surface failure, not a pass.

### M2. A configured default_surface is replaced silently when it fails the promotion bar (FIXED)
> **Fix:** `warn_if_default_not_promoted` emits a LoadWarning naming agent, declared default, used surface and missing validation; surfaced by spawn-agent and wait-idle; CLI-seam test added.

**Source:** CLAUDE-2 (Codex agrees), narrowed by the orchestrator
**Files:** `core/src/agents/mod.rs:130-137`, `core/src/agents/mod.rs` (config load/warnings), `tests/integration.rs`

`AgentSpec::default_surface()` falls back to the pre-surface rendering whenever the named default lacks a stamped ready/busy pair. That fallback is required: AC3 says an agent whose flat surface lacks a validated `busy_regex` records its pre-surface rendering, so the gate stays. But it applies to any surface a user's `agents.toml` names as `default_surface`, including rich surfaces that are never required to carry patterns. The override is silent: spawn-agent records a different surface than the file declares, and no load warning is emitted. The -02 fixture `surface_agent_toml` had to gain `busy_regex` and `validated_version` to keep its old behavior.

**Required outcome:** keep AC3's fallback. Whenever the fallback overrides a `default_surface` that `agents.toml` explicitly declares, the load path emits a warning through the existing agents.toml warning channel. The warning names the agent, the declared default, the surface actually used, and the missing validation. A test at the CLI seam proves the warning appears and the pre-surface surface is recorded.

### M3. The smoke's ready_regex check is circular and never tests ready_regex against generating frames (FIXED)
> **Fix:** idle and turn end established independently (native boot chrome, byte-stable, not busy); `ready_matched_during_generation` fails on any ready match from the first to the last busy frame, including ready-only frames; unit-tested.

**Source:** CLAUDE-4 (Codex agrees)
**Files:** `src/bin/tt-vendor-smoke.rs:50-80`, `src/bin/tt-vendor-smoke.rs:217-222`, `src/bin/tt-vendor-smoke.rs:270-279`, `src/bin/tt-vendor-smoke.rs:404-454`

The idle capture is chosen when `idle_evidence` matches. That evidence is identical to, or a subset of, the declared `ready_regex` (dsh flat `● ready ·`; claude `✓ done \| 🤖`; codex `· Ready ·`). So `classify(idle) == Idle` holds by construction. `check_busy` stops at the first Busy frame and never checks whether `ready_regex` also matches while the agent is generating. That premature-ready failure is exactly what the patterns exist to prevent.

**Required outcome:** idleness is established independently of the declared `ready_regex`, for example by a pane whose content stays static for a fixed window after launch or after a completed turn. The busy phase samples frames throughout generation and fails if `ready_regex` matches any of them.

### M4. Version check passes on a substring match (FIXED)
> **Fix:** `versions_match` compares parsed version tokens for equality; unit tests cover prefix-adjacent and prerelease cases.

**Source:** CLAUDE-5 + CODEX-6 (both reviewers)
**Files:** `src/bin/tt-vendor-smoke.rs:380-395`

The stamp is accepted when `declared.contains(live_token)`. So live `2.1.27` matches the stamp `claude 2.1.278`, and live `dsh 0.1.5` matches `dsh 0.1.5-rc.1`, and the smoke reports PASS against a binary other than the stamped one.

**Required outcome:** parse the version token out of both the stamp and the live `--version` output and require exact equality. Add a unit test covering prefix-adjacent and prerelease cases.

### M5. claude status-line busy pattern misses the permission and background-task busy states (FIXED)
> **Fix:** status-line patterns declared under `[claude.surfaces.rich]` with busy_regex covering working/permission/bg; a core test loads the shipped example through the real loader and classifies every busy state as Busy.

**Source:** CLAUDE-3 (Codex agrees)
**Files:** `core/src/agents/builtin.rs:147` (or wherever H1 moves the status-line patterns), `examples/claude-statusline/statusline-command.sh:8-10,42-49`

The status line marks `🔐 permission |` and `⚙ N bg… |` as busy, but the declared `busy_regex` matches only `⚡ working \| 🤖`. In those states the pane classifies as Unknown, and idle fallback fires on a static permission prompt, so `wait-idle` reports completion while the agent is blocked mid-turn.

**Required outcome:** wherever the status-line patterns are declared after H1, the busy pattern covers every busy indicator the status line emits, or the declaration documents why a state is deliberately left Unknown.
