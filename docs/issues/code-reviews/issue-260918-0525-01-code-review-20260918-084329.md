### M1. Reported alternate-screen state can race the capture (FIXED)
> **Fix:** single tmux invocation (`display-message -p … ; capture-pane …`) split at the first newline; unit tests on the split; CLI race test waived as non-deterministic.

**Source:** CODEX-1 · cross-verified by claude
**Files:** `src/cmd/capture.rs:33-40`

`capture --all` reads `#{alternate_on}` with one `tmux display-message` process and runs `capture-pane` in a second process. A pane that switches screens between the two calls produces stdout from one state while stderr and `scrollback_available` describe the other. This breaks P4's requirement that the report reflects the live state the capture saw.

**Required outcome:** read the flag and the capture in one tmux invocation (`display-message -p -t P '#{alternate_on}' \; capture-pane -p -t P -S -`), splitting the flag line from the body at the first newline. Cover the flag/body split with a unit test. A deterministic CLI-level race test is not required.

### L1. Shortfall test's expected line count comes from the response under test (FIXED)
> **Fix:** compares `lines` with an independent direct `tmux capture-pane` oracle; asserts oracle and output are non-empty.

**Source:** CODEX-2 · cross-verified by claude
**Files:** `tests/integration.rs:1345-1357`

The test asserts that JSON `lines` equals `output.lines().count()` from the same response, and only checks `actual < requested`. A regression returning `output: ""` with `lines: 0` would still pass.

**Required outcome:** compare against an independent oracle, such as a direct `tmux capture-pane -p` of the fixture pane, and assert that the capture is non-empty.
