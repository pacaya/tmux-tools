### H1. Pattern-bearing surfaces lose idle-detection completion (FIXED)
> **Fix:** idle detection runs whenever the classified state is Unknown (no surface, no patterns, or ambiguous); Busy suppresses it; README/CONTEXT/ADR aligned; 3 CLI tests plus a cursor quiet-pane fallback test.

**Source:** CLAUDE-1, CLAUDE-2 · Codex disagreed on direction (CODEX-5); adjudicated inline
**Files:** `core/src/idle.rs:211-244`, `README.md:134`, `CONTEXT.md:36`, `CONTEXT.md:46`, `docs/adr/260919-0146-01-agent-surfaces.md:66`, `docs/adr/260919-0146-01-agent-surfaces.md:83`

`patterns.is_none()` turns idle detection off whenever the resolved surface has any pattern. At base, a static pane whose `ready_regex` did not match still completed as `idle` after `--idle-seconds`. Now a `cursor` or `agy` pane that goes quiet without its ready footer, and any busy-only surface, ends only at `--timeout` (in `wait-idle` and `prompt`). This violates acceptance item 8 ("`wait-idle` behaving as before") and the Outcome ("Every agent's default surface stays what it is today"). P3 names P5/P7 as the consumers that must branch on Unknown for certainty; `wait-idle` is not one of them.

**Required outcome:** when the classifier returns Unknown, idle detection stays the completion fallback. When it returns Busy, idle detection is suppressed. When it returns Idle, the ready debounce still applies (`ready_matched`). No patterns or no surface still uses idle detection alone. Make README, CONTEXT.md (**Readiness**, **Idle detection**) and the ADR say the same thing: idle detection decides only when the classifier cannot (no patterns, no surface, or Unknown), never overrides Busy, and is not a parallel definition of idleness. Add CLI tests with `tt-fake-tui`:
- a pane on a surface with patterns that sits static without its ready footer settles as `idle`;
- a busy-only surface settles as `idle` once its busy footer is gone;
- a pane showing a static busy footer does not settle as `idle` before timeout.

### M1. Stale recorded surface is reinterpreted as the pre-surface rendering (FIXED)
> **Fix:** resolve_surface branches on record presence; stale record → no surface; unit test corrected; CLI test `stale_recorded_surface_resolves_to_no_surface`.

**Source:** CLAUDE-3, CODEX-1 · cross-verified by both
**Files:** `core/src/agents/mod.rs:375-383`, `core/src/agents/mod.rs:1308-1310`

`resolve_surface` falls through to `pre_surface()` when `@tt-surface` is present but names a surface the registry no longer has. That applies another rendering's patterns to the pane, which breaks P2's "record present → that surface; record absent → the pre-surface rendering". The unit test at `:1308-1310` locks in the wrong fallback.

**Required outcome:** branch on whether a record is present. A record naming a known surface resolves to that surface. A record naming an unknown surface resolves to no surface, which behaves as unknown and uses idle detection in `wait-idle`/`prompt`. Only an absent record resolves to `pre_surface()`. Fix the unit test, and add a CLI test for a pane whose recorded surface is missing from the registry.

### M2. `prompt` delivers the prompt before validating surface patterns (FIXED)
> **Fix:** surface patterns and full IdleConfig built before capture/send; CLI test `prompt_invalid_surface_regex_sends_nothing`.

**Source:** CODEX-2 · cross-verified by claude
**Files:** `src/cmd/prompt.rs:50-60`, `src/cmd/wait_idle.rs:110-141`

`send_prompt` runs before `surface_patterns_for` reads the registration, loads the registry, and compiles `ready_regex`/`busy_regex`. An invalid `busy_regex` (a new failure point this diff adds) or a registry error fails after the agent has already received the prompt, so a retry submits it twice.

**Required outcome:** resolve and compile the surface patterns and build the full wait configuration before capturing or sending. Add a CLI test: an invalid surface regex makes `prompt` fail without sending any text to the target pane.
