BLOCKER: Acceptance item 5 says "after a new pane named `p` is created, `c` stays `orphan: true`". `launched_at` has whole-second resolution and `launched_later` compares strings with a strict `>`. ### M7. A large negative `-S` overflows the Orca history range (FIXED)
> **Fix:** Saturating u64 sum through `u32::try_from`; `Tail(n)` when it fits, else `All`; fake-orca boundary test (incl. i64::MIN).

Source: CODEX-7 (a regression from the M4 fix; the orchestrator verified it directly). `src/shim.rs:536-542`.

BLOCKER: `start.unsigned_abs() as u32 + visible` truncates the i64 and adds with no overflow check. On Orca, `capture-pane -p -S -4294967295` panics in a debug build and wraps to a short tail in a release build. `-S -4294967296` truncates to 0. This breaks P5.6 history capture and the P5.8 rule that the Shim exits only 0 or 1.

Required outcome: a negative `-S` of any size returns the available history and never panics or wraps (for example: saturating conversion and addition, or `All` beyond the `Tail` limit). Add a boundary test through the fake-`orca` CLI seam.
