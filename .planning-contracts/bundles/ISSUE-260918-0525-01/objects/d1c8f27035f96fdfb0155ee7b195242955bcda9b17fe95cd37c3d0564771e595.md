## Agent Brief

**Outcome and scope:** `capture --all` states when the target pane cannot supply scrollback, and the
repository gains the `tt-fake-tui` test fixture.

**Required sources:** `tmux-tools:PRD-260918-0323-01#p4-capture` (the behavior);
`tmux-tools:PRD-260918-0323-01#verification` (fixture shape and gating).

**Current observable:** `capture --all` against a pane with `alternate_on=1` returns the pre-launch
shell lines plus the visible screen, and says nothing about it. SKILL.md and README.md state that
`--all` returns full history.

**Required change:**
- P4 as written: decide from the live `alternate_on` pane state, not from a recorded surface; raw
  and concise stdout stay byte-identical and the notice goes to stderr; JSON gains a structured
  field; a `--lines N` shortfall stays silent.
- Add `tt-fake-tui` as a second `[[bin]]` behind a cargo feature via `required-features`, so a
  normal install does not ship it, reachable from integration tests as
  `CARGO_BIN_EXE_tt-fake-tui`. This packet needs only one of its behaviors: optionally switching to
  the alternate screen.
- Document the project's test command, with the feature enabled, where contributors will find it.
  A bare `cargo test` running fewer tests is accepted.
- Correct the SKILL.md and README.md statements about `--all` so they state the limit.

**Acceptance:**
- [ ] Given a fixture pane on the alternate screen, when `capture --all` runs in raw and in concise
  format, then stdout is byte-identical to the pre-change output and stderr carries a notice that
  full history is unavailable, observable at the CLI.
- [ ] Given the same pane, when `capture --all --format json` runs, then the JSON carries a
  structured field saying scrollback is unavailable, observable at the CLI.
- [ ] Given a fixture pane that entered the alternate screen after launch, when `capture --all`
  runs, then stderr carries the notice and JSON says scrollback is unavailable; given one that left
  it, then there is no notice and JSON does not say so, observable at the CLI.
- [ ] Given a normal-screen pane with fewer lines than a `--lines N` request, when `capture` runs,
  then no notice is emitted on stderr, and `--format json` reports the actual `lines` count without
  saying scrollback is unavailable.
- [ ] SKILL.md and README.md no longer say `--all` returns full history and state the
  alternate-screen limit, observable in those files.
- [ ] The documented test command builds `tt-fake-tui` and runs the tests using it; a bare
  `cargo test` finishes green without them, observable in test output.
- [ ] Given a normal `cargo install` / `cargo build` without the feature, then no `tt-fake-tui`
  binary is produced, observable in the build output.

**Verification and release:** Integration tests at the CLI seam against a real tmux server
(`tests/integration.rs`), run with the documented test command; full workspace suite green.

**Out of scope:** Surfaces and any registry change; fixture behaviors other than the alternate
screen; making `--all` an error; P7's completeness reporting.
