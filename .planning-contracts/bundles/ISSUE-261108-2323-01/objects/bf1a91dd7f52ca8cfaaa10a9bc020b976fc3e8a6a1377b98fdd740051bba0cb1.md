### P10 — Contract tests per Claude version

1. The Claude version key is the first blank-separated word of `ClaudeBinary.version` (`2.1.319` for `2.1.319 (Claude Code)`). The fixture name, the P10.5 match, and the P10.5 warning use this key. A trace fixture per Claude version, `tests/fixtures/claude-teams/<version key>.jsonl`, holds every tmux argv that this Claude version sends in teammate mode. Each line is one JSON object `{"argv":[string],"exit":number,"stdout":string}`: `argv` is the argv after `argv[0]`, `exit` the expected exit code, `stdout` the expected complete stdout. In `argv` and `stdout`, the team id, the cwd, and the Claude binary paths (P10.3) are the placeholders `{{team_id}}`, `{{cwd}}`, and `{{claude}}`. The first fixture is for Claude 2.1.319.
2. The default `cargo test --workspace --features test-fixtures` run replays each fixture through the real binary started as `tmux` (P5.1), inside a Team on the isolated tmux test server, with no Orca. A fake `claude` script on `PATH` replays the fixture and exits 0 or 1. Replay fills the placeholders with the replay Team's values (`{{claude}}` = the path of the fake `claude`); the Shim's stdout must equal the filled `stdout` exactly, and its exit must equal `exit`; the tests check P2.5, P6, P7, and P8 through the CLI (`list --format json`, `self --format json`). One test, in a 120×24 window, starts teammates until a `split-window` exits 1 with `tmux: no space for a new pane`, then respawns teammate `tm1` once. It records in the test output the maximum teammate count and the respawn result. It passes when the failed start creates no pane and no registration, and the respawn either exits 0 or exits 1 with `tmux: no space for a new pane` while the old pane and its registration stay.
3. An opt-in live test (environment switch, never by default) runs the real `claude` under `claude-teams` on the isolated tmux server with `TT_SHIM_DEBUG=1`, `disableAllHooks: true`, and the Bash tool disallowed (`--disallowedTools Bash`, so every Shim call comes from Claude itself and not from a Leader tool call), makes it spawn one teammate, reads `shim-debug/<team id>/` (P4.5) after Claude exits, and fails when the Claude version has no fixture or when its `shim.log` has a `refused` line whose `argv`, with the P10.1 placeholders filled, equals the `argv` of no fixture line with `exit` 1. A fixture line with `exit` 1 records a call that this Claude version makes and that the Shim refuses by P5.8 (for Claude 2.1.319: the startup probes `show -Av mouse`, `show -gv focus-events`, and `show-environment -g`). A new Claude version gets its fixture from a `shim.log` written with `TT_SHIM_DEBUG=1`, from this run or from any other run. The fixture tool is the test helper binary `tt-fixture` (`src/bin/tt-fixture.rs`, declared in `Cargo.toml` with `required-features = ["test-fixtures"]` as `tt-fake-tui` is, so the release build does not contain it): `cargo run --features test-fixtures --bin tt-fixture -- <shim.log> > tests/fixtures/claude-teams/<version key>.jsonl`. It parses each JSONL line of `shim.log` (P5.9), takes `argv`, `exit`, and `stdout`, and replaces the team id, the cwd, and the Claude binary paths `ClaudeBinary.resolved` and `ClaudeBinary.path` of that Team (from the `team.json` in the same directory as the given `shim.log`) with the placeholders of P10.1; both Claude paths become `{{claude}}`. Over these four values, it replaces the longest value first.
4. The Shim fails closed: an unknown command or flag exits 1 (P5.8); the Shim never guesses.
5. When the Claude version that the Launcher records has no fixture in the binary's build, the Launcher prints `claude-teams: claude <version key> not contract-tested` on stderr once and continues.
6. The Orca contract run of PRD-261107-0825-01 P10.2 adds: a Team with one teammate whose pane shows in `orca terminal list` and in `tmux-tools list` with `team` and `parent`; Orca reports `agentIdentity` `claude` for the teammate pane (`orca terminal list --json`); the Leader has the teammate print its `ORCA_PANE_KEY`, `ORCA_TERMINAL_HANDLE`, and `ORCA_TAB_ID`, each of the three values equals the value of the teammate pane's row in `orca terminal list --json` (`ORCA_TERMINAL_HANDLE` = `handle`, `ORCA_TAB_ID` = `tabId`, `ORCA_PANE_KEY` = `<tabId>:<leafId>`, PRD-261107-0825-01 P9.10), and the `ORCA_PANE_KEY` and `ORCA_TERMINAL_HANDLE` values differ from the Leader pane's values (P6.5); Orca shows the teammate's status on its own pane, not on the Leader pane (P6.5); a clean leader exit that closes the teammate; a leader crash that leaves an Orphan that `list` reports. Each run closes every pane it created and ends with no leaked pane (PRD-261107-0825-01 P10.4). A run before harness PRD-261108-0235-01 rollout steps 2 (hooks) and 3 (text and scripts) are released runs all of these checks and starts the Leader's Claude with `disableAllHooks: true` (harness P9.6).
